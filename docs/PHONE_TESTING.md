# Android에서 테스트

## Vercel HTTPS 주소로 접속

1. 배포 완료 후 안내된 **고정 Production 주소**를 Android Chrome에서 엽니다. USB, 같은 Wi-Fi, PC 실행은 필요하지 않습니다.
2. 자주 사용하면 Chrome 메뉴의 **홈 화면에 추가 / 앱 설치**를 선택합니다. 메뉴 이름은 Chrome 버전에 따라 다를 수 있습니다.
3. 수정 사항은 GitHub에 push하면 연결된 Vercel 프로젝트가 다시 빌드합니다. 같은 고정 주소를 계속 사용하세요. 새 버전 안내가 뜨면 저장 후 업데이트합니다.
4. 코스·직접 올린 사진은 여전히 **그 기기의 브라우저**에 저장됩니다. PC에서 만든 코스를 옮기려면 전체 백업 파일을 폰으로 보내고 설정 → 파일 가져오기를 사용하세요. 자동 계정 동기화는 없습니다.

## 확인할 동작

- 보관함: 사진이 없는 카드는 **모든 지점이 보이는 정지 지도**. 카드 위에서는 지도 제스처를 받지 않습니다.
- 코스 진입: 모바일은 모든 장소가 보이는 지도부터 시작합니다. **일정** 탭에서 장소·사진·구간 이동을 편집합니다. 새 빈 코스는 편집 화면부터 시작합니다.
- 지도: 한 손가락 이동, 두 손가락 핀치 확대·축소, 회전, 두 손가락을 나란히 위아래로 움직여 기울이기.
- 장소 번호 선택 → 해당 장소로 이동. **전체** → 모든 위치가 보이는 2D 개요로 복귀. 나침반 버튼으로 북쪽·2D 기울기 초기화.
- 자동 둘러보기 중 직접 지도를 만지면 투어가 멈춥니다.
- **앱 안에서 경로 비교**: 좌표가 있는 두 장소를 준비합니다. **일정**에서 이동 줄을 펼치고 **대중교통 → 대중교통 경로 조회**를 선택합니다. 후보의 소요 시간, 환승, 승하차 지점과 제공된 요금을 비교합니다.
- **지도와 적용**: 지도 하단에서 같은 구간의 후보를 열고 **지도에서 보기**를 선택합니다. 적용 전에는 저장된 이동 시간이 유지되는지 확인합니다. 편집 가능한 구간에서 **일정에 적용**을 누른 뒤 이동 시간과 이후 방문 시각을 확인하고, 새로고침해 적용 상태가 남는지 봅니다. 지도 경로선은 운영 설정과 응답 좌표에 따라 표시됩니다.
- **현재 도착정보**: 후보의 버스·지하철 단계에서 **도착정보**를 열고 정류소·역, 노선, 제공처와 조회 시각을 확인합니다. 별도로 **경로·버스** 화면에서 장소 주변 정류소 도착정보를 조회합니다.
- **조회 제한과 외부 확인**: 미연결·한도·빈 결과 안내가 표시되어도 기존 일정과 직접 입력이 유지되는지 확인합니다. 보조 링크를 시험할 때는 네이버의 장소명 검색 결과와 카카오의 좌표 기반 위치를 각각 확인합니다. 외부 페이지가 열리는 동작은 앱의 후보 조회와 일정 적용 검사에서 별도로 기록합니다.
- 일정 보기 → 사진 추가 → 새로고침 후 유지 → 사진 삭제 → 기본 지도 커버로 복귀.
- 사진과 이동 경로가 포함된 코스 파일을 내보내고 다시 가져왔을 때 내용이 함께 복원되는지 확인합니다.

### 교통 검증 기록 남기기

| 확인 항목 | 함께 기록할 정보 |
| --- | --- |
| 앱 내 후보 조회 | 출발·도착, 화면 진입 방식, 후보 수 또는 오류, 조회 시각 |
| 미리보기와 일정 적용 | 미리보기 전후 이동 시간, 적용 후 방문 시각, 새로고침 뒤 상태 |
| 실시간 도착정보 | 정류소·역, 노선과 방면, 제공처, 조회 시각 |
| 외부 지도 | 브라우저·지도 앱이 열린 결과와 실제 선택된 위치 |

키 또는 활성화 설정이 빠졌다면 [교통 API 설정](../README.md#교통-api-환경변수-선택-연결)을 확인하세요. 운영 확인 스크립트의 기본 모드는 앱 배포와 기능 설정을, `--arrivals`는 일부 실시간 도착정보를 검사합니다. 신규 경로 조회와 일정 적용은 위의 브라우저 절차로 확인합니다.

## 문제를 발견했을 때

어느 화면·어느 버튼에서 발생했는지, 재현 순서, Android/Chrome 버전, 스크린샷을 함께 알려주세요. 설정과 데이터에서 앱 버전을 확인할 수 있습니다.

Vercel의 서버/빌드 로그만으로 휴대폰 브라우저 안의 JavaScript 오류를 모두 볼 수 있는 것은 아닙니다. 상세 콘솔이 필요할 때는 PC Chrome의 [Android 원격 디버깅](https://developer.chrome.com/docs/devtools/remote-debugging)을 사용합니다. 단순 화면·터치·저장 테스트에는 USB가 필요 없습니다.

Production과 매번 달라지는 Preview URL, Chrome 일반 탭과 다른 브라우저는 보관함이 다를 수 있습니다. 테스트 데이터가 유지돼야 하면 고정 주소와 같은 브라우저를 사용하세요.

## 배포 조건

현재 개인·비상업 테스트는 Vercel Hobby 범위로 구성합니다. 무료 제공량에는 한도가 있으며, 상업 운영 단계에서는 [Vercel 요금제 조건](https://vercel.com/docs/plans/hobby)을 다시 확인해야 합니다. 유료 지도 API, DB, 사진 업로드 서버는 추가하지 않았습니다.

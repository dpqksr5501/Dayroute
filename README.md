# Dayroute

서울·경기에서 가고 싶은 장소를 모아 하루 코스를 만드는 웹앱입니다. 지도와 일정에서 방문 순서, 체류 시간과 이동 시간을 살피고, 구간별 대중교통 후보를 비교해 일정에 반영할 수 있습니다. 완성한 코스는 브라우저에 보관하거나 사본으로 공유합니다.

## 실행

이 컴퓨터에서는 루트의 **`Start-Dayroute.cmd`를 더블클릭**하고, 표시되는 `http://127.0.0.1:5173`을 브라우저에서 여세요. 이미 서버가 실행 중이면 기존 주소를 사용하세요. 창에서 Ctrl+C를 누르면 서버를 종료합니다.

일반 개발 환경에서는 Node.js 24 LTS와 pnpm이 필요합니다. VS Code로 이 폴더를 열면 됩니다. 별도 Visual Studio 워크로드·DB·Docker는 필요하지 않습니다.

```sh
pnpm install --ignore-scripts
pnpm dev
pnpm test
pnpm build
pnpm preview
```

`dev`: 개발·자동 새로고침. `preview`: 빌드 결과, PWA 캐시·업데이트 확인. 홈 화면 설치 및 서비스 워커는 HTTPS 또는 localhost에서 동작합니다. PWA 앱 설치 방식은 OS·브라우저에 따라 다릅니다.

Vercel 배포 및 Android 테스트는 [휴대폰 테스트 가이드](docs/PHONE_TESTING.md)를 참고하세요. `vercel.json`에서 `package.json`에 지정된 pnpm으로 잠금 파일 그대로 설치하고, Vite 빌드·출력 경로와 업데이트용 캐시 헤더를 설정합니다. 설치와 빌드에서 npm을 실행할 때 npm이 지원하지 않는 `npm_config_cache_dir`만 빼고 pnpm의 캐시 설정은 유지합니다. 로컬 개발에는 Node.js 24 LTS를 사용하며, Vercel 빌드의 Node.js 버전은 프로젝트 설정에서 관리합니다.

운영 배포 후 `pnpm verify:deployment`로 HTML, 앱 번들, 보안 헤더, 교통 함수의 시작과 설정 상태를 확인합니다. `pnpm verify:deployment --arrivals`는 성동13·성수역 2호선 실시간 응답도 확인합니다. 두 검사 모두 TMAP 경로 한도를 사용하지 않습니다. Preview URL을 확인할 때는 `pnpm verify:deployment <URL> --preview`를 실행합니다.

## 현재 기능

- 여러 코스 생성·검색·지역 필터·즐겨찾기·복제·삭제·실행 취소
- 장소 카드와 일정 편집: 순서, 날짜, 시작 시각, 체류·이동 시간, 이동수단(`도보`/`대중교통`/`자동차`), 예약 여부, 메모
- 일정의 이동 구간이나 지도 하단에서 **대중교통 후보를 조회하고 비교**합니다. 버스·지하철/열차·혼합·도보 등으로 필터링하고, 추천·소요 시간·환승·도보 시간·요금으로 정렬합니다.
- 후보에서 예상 소요 시간, 승하차 지점, 이동 단계와 제공된 요금을 확인합니다. 지도 하단의 **지도에서 보기**로 후보를 미리 볼 수 있으며, 편집 가능한 일정 구간은 **일정에 적용**을 눌러 이동수단과 소요 시간을 반영합니다.
- **도보·자동차** 예상 시간과 거리는 TMAP에서 조회합니다. 지도에 도로 경로선을 표시하려면 별도 표시 설정이 필요합니다.
- **실시간 도착정보**는 후보 카드에서 버스·지하철의 승차 지점과 노선을 기준으로 따로 조회합니다. 제공처와 조회 시각, 응답에 포함된 방면을 표시합니다.
- 주변 버스 도착 모달(`BusPanel`): 코스 내 장소 기준 반경 500m 서울(TOPIS)·경기(GBIS 및 경기데이터드림 이중 연동) 정류소 검색 및 실시간 버스 도착 조회
- 서울·경기 기본 장소 목록 검색 + **TMAP 실시간 장소(POI) 통합 검색** + 지도 클릭 시 **리버스 지오코딩 주소 자동 입력**
- 무료 벡터 지도, **광원(Light)·높이별 그라데이션 입체 건물(3D)**, 외곽선(Casing) 경로 라인 및 대중교통 승하차 지점 표시, 장소 포커스·순차 카메라 투어, **2D/3D 전환 버튼** 및 북쪽 초기화 나침반
- 기본 코스 커버는 모든 위치가 들어오는 정지 지도 이미지. 화면 근처 카드만 공용 렌더러 하나로 순차 생성하고 메모리에서 재사용
- 지도 이미지 생성 실패·오프라인에서는 좌표 기반 동선 그림으로 대체. 위치가 없으면 빈 커버 유지
- 직접 사진 추가·변경·삭제: 브라우저에서 축소·WebP 변환 후 로컬 저장, 사진 삭제 시 동선으로 복원
- 브라우저 자동 저장, 새로고침 복원, JSON 파일 백업·가져오기, 일정 텍스트 복사
- 보기 전용 미리보기와 배포 후 URL fragment에 코스를 담는 사본 공유
- 반응형 모바일 레이아웃, 키보드 순서 이동, reduced-motion 대응
- 배포 버전 확인: 실행·화면 복귀·온라인 복구 시 확인, 사용 중에는 저장 후 적용
- 프로덕션 서비스 워커: 앱 파일 캐시, 지도 타일은 오프라인 캐시하지 않음

처음 보이는 3개 코스는 예시입니다. 기본 장소 좌표·주소도 방문 전 확인해 주세요. 기존 분위기 사진은 제거했습니다.

## 일정에서 경로를 고르는 방법

1. **일정**에서 두 장소 사이의 이동 구간을 펼치고, 이동수단을 대중교통으로 바꾼 뒤 **대중교통 경로 조회**를 선택합니다. **지도**에서는 하단에서 구간을 선택하고 후보를 펼칠 수 있습니다. 두 장소의 지도 위치가 필요합니다.
2. 후보에서 소요 시간, 환승, 도보 시간과 제공된 요금을 비교합니다. 예상 도착 시각은 일정상의 출발 시각에 예상 소요 시간을 더해 계산합니다. **내 위치 → 첫 장소**는 조회 시각을 기준으로 보여 줍니다. 날짜별 시간표는 별도로 확인해야 합니다.
3. 지도 하단에서 후보를 미리 보거나, 편집 가능한 장소 간 구간에서 **일정에 적용**을 누릅니다. 적용 전에는 저장된 일정이 바뀌지 않습니다. 내 위치에서 첫 장소까지의 후보는 조회용입니다.
4. 조회가 제한되거나 결과가 비어 있으면 기존 일정은 유지됩니다. 편집 화면에서 이동 시간을 직접 입력할 수 있습니다. 외부 지도에서 추가로 확인하고 싶을 때는 보조 링크를 엽니다. 네이버 지도에는 출발·도착 **장소명**을 전달하며, 카카오맵에는 **장소명과 좌표**를 전달합니다. 외부 서비스에서 열린 경로의 출발·도착 위치를 확인해 주세요.

## 비용과 기능의 경계

보관함, 일정 편집과 기본 지도는 교통 API 설정 없이 사용할 수 있습니다. 경로, 도착정보, 실시간 장소 검색은 해당 서버 환경변수와 활성화 조건을 갖춘 항목부터 사용할 수 있습니다. 기본 지도는 OpenFreeMap 공개 인스턴스를 사용합니다.

| 항목 | 현재 구현 |
| --- | --- |
| 지도 | MapLibre GL JS + OpenFreeMap / OpenStreetMap |
| 입체 건물 | OSM 건물 형태·높이 기반, 지역별 밀도·정확도 차이 있음 |
| 실사 건물·항공 3D | 미연결. Google/V-World 등의 해당 지역 데이터·사용 조건을 먼저 검토해야 함 |
| 도보·자동차 경로 | 기본은 직선 점선·직접 입력 시간. `TMAP_APP_KEY` 및 `TMAP_FREE_PLAN_CONFIRMED=true` 설정 시 예상 시간·거리 조회. `TMAP_MAP_DISPLAY_CONFIRMED=true` 설정과 유효한 경로 좌표가 있으면 도로 경로선 표시 |
| 대중교통 경로 | ODsay 키가 있으면 ODsay를 사용합니다. ODsay 키가 없을 때는 TMAP 키와 대중교통 또는 무료 요금제 확인 설정이 필요합니다. 후보 조회·정렬·일정 적용과 지도 도형 표시는 별도 기능입니다. 도형 표시는 `TRANSIT_MAP_DISPLAY_CONFIRMED=true`와 제공처 응답에 따릅니다. |
| 실시간 도착 | `SEOUL_BUS_SERVICE_KEY` / `GYEONGGI_BUS_SERVICE_KEY` / `SEOUL_SUBWAY_SERVICE_KEY` 연결 시 주변 정류소 및 대중교통 경로 첫 탑승 지점 실시간 도착 조회 |
| 장소 검색 | 기본 장소 목록 및 TMAP 키 연결 시 실시간 장소 검색 |
| 영업시간·휴무·날씨·웨이팅 | 미연결. 자동 검증됐다고 표시하지 않음 |
| 공동 편집·계정 동기화 | 미구현. 현재 브라우저 로컬 보관함 |
| 호스팅 | 로컬 개발과 Vercel 배포가 같은 `api/transport.ts` 사용 |

### 교통 API 환경변수 (선택 연결)

로컬(`.env.local`) 또는 Vercel 프로젝트의 **Settings → Environment Variables**에 사용할 기능의 키와 확인 값을 설정합니다. 경로 제공처, 실시간 도착정보 제공처, 지도에 경로선을 표시하는 설정은 각각 관리합니다. `/api/transport?action=status`에서 현재 설정 상태를 확인할 수 있습니다.

```ini
# 도보 및 TMAP 대중교통 경로 탐색
TMAP_APP_KEY=발급받은_SK_OpenAPI_앱키
TMAP_FREE_PLAN_CONFIRMED=true
TMAP_TRANSIT_CONFIRMED=true
TMAP_MAP_DISPLAY_CONFIRMED=true

# ODSay 대중교통 경로 탐색 (선택)
ODSAY_API_KEY=발급받은_ODSay_API_키
TRANSIT_MAP_DISPLAY_CONFIRMED=true

# 서울·경기 실시간 버스 및 서울 실시간 지하철 도착
SEOUL_BUS_SERVICE_KEY=공공데이터포털_서울버스_서비스키
GYEONGGI_BUS_SERVICE_KEY=공공데이터포털_경기버스_서비스키
SEOUL_SUBWAY_SERVICE_KEY=서울열린데이터광장_실시간지하철_인증키
```

공식 자료: [OpenFreeMap](https://openfreemap.org/), [Quick start](https://openfreemap.org/quick_start/), [MapLibre 입체 건물 예제](https://maplibre.org/maplibre-gl-js/docs/examples/display-buildings-in-3d/).

## 보관·공유·개인정보

- 사용자 코스와 사진은 현재 사용 중인 브라우저의 IndexedDB 보관함에 저장됩니다.
- 사진은 JPG·PNG·WebP, 원본 12MB·4,800만 화소 이하를 지원합니다. 긴 쪽 최대 1,280px·저장 문자열 최대 180,000자로 줄여 WebP로 저장하며 원본 파일과 EXIF를 보관하지 않습니다. 외부 업로드는 하지 않습니다.
- 사진도 코스 복제·파일 백업·가져오기에 포함됩니다. 저장 한도를 넘는 변경은 거절하고 이전 저장 내용을 유지합니다. 저장할 때 계산하는 보관함 크기와 가져오기 파일 크기는 별도로 검사합니다. 한도에 가까운 전체 백업은 [검증 기록](docs/VALIDATION.md)의 파일 크기 항목을 참고하세요.
- 브라우저 데이터 삭제·다른 브라우저·다른 포트·다른 기기는 별도 보관함입니다. 중요한 코스는 설정 → 전체 백업으로 보관하세요.
- 파일 가져오기는 기존 코스를 유지하며 새로운 ID로 코스를 추가합니다. 최대 500코스, 코스당 100장소, 파일 5MB.
- 저장 실패·손상된 데이터는 정상 데이터로 덮어쓰지 않고 안내합니다. 복구 가져오기 전에 원본 문자열 백업을 내려받습니다.
- 첫 편집에서 이전 형식인 `localStorage`의 `dayroute.library.v1` 코스를 트랜잭션으로 옮기고 기존 저장본을 복구용으로 남깁니다. 이후에는 바뀐 코스와 보관함 순서만 저장하며, 저장 중 들어온 연속 편집은 최신 상태로 합칩니다.
- 보관함 버전 비교와 변경 저장은 같은 트랜잭션에서 처리합니다. 다른 탭이 먼저 저장했으면 최신 데이터가 유지되고, 이 탭의 변경은 백업할 수 있습니다. 가져오기는 최신 보관함에 사본을 추가합니다. 브라우저 보관함은 공동 편집용 데이터베이스가 아닙니다.
- 이 버전에서 저장한 최신 코스는 IndexedDB에 있습니다. 이전 앱 빌드로 되돌리면 그 빌드는 이전 `localStorage` 사본을 읽습니다. 운영 코드를 되돌려야 하면 IndexedDB를 읽을 수 있는 수정 배포를 우선하고, 이전 빌드에서 수정하기 전에 현재 버전에서 전체 백업을 받으세요.
- 업데이트 전 탭에서 저장한 내용은 설정 → **이전 버전 저장본 백업**에서 따로 내보낼 수 있습니다. 현재 탭이 열려 있는 동안 이전 탭에서 저장한 내용이 감지되면 안내합니다.
- 배포 후 보기 전용 링크는 서버 DB 없이 URL fragment(`#share=…`)에 코스 사본을 포함합니다. 일반 HTTP 요청에 fragment는 포함되지 않지만, **링크를 가진 사람은 일정·메모·위치를 볼 수 있습니다**. 암호화·접근제어·회수·자동 만료는 없습니다. 민감한 메모는 공유하지 마세요.
- 이미 공유한 사본은 이후 편집과 무관합니다. 로컬 주소는 다른 사람에게 보내도 접속되지 않으므로 파일·텍스트 공유를 안내합니다.
- URL 공유 사본에서는 사진을 제외합니다. 사진까지 보내려면 코스 파일로 공유하세요. 링크 길이와 의도하지 않은 사진 포함을 피하기 위한 동작입니다.
- 지도 제공자에는 표시 영역의 지도 요청이 전송됩니다. Google Fonts에는 글꼴 요청이 전송됩니다. **내 위치**를 누르면 브라우저에 위치 권한을 요청합니다. 허용하면 주소 및 첫 장소까지의 경로 조회에 현재 좌표를 사용합니다. 현재 위치는 코스 보관함과 공유 사본에 저장하지 않습니다.

## 교통 요청과 운영 보안

- 브라우저의 동시 요청은 URL 쿼리 순서에 관계없이 공유합니다. 한 화면의 취소는 다른 화면의 요청에 영향을 주지 않습니다. 마지막 화면이 취소하면 진행 중인 요청을 중단합니다.
- 지도 화면을 여는 것만으로는 대중교통 후보를 조회하지 않습니다. 후보 펼치기, 이동 구간 선택 또는 대중교통 안내 열기에서 조회합니다.
- 도보·자동차 지도 표시 권한이 설정된 경우에만 지도 미리보기용 좌표를 자동 조회합니다. 일정에서 직접 시간·거리를 요청하는 기능은 계속 사용할 수 있습니다. 대중교통 조회가 일시 제한되면 브라우저에서도 서버의 재시도 대기 시간을 지킵니다.
- 주변 정류소와 경로 카드가 같은 정류소의 도착정보를 요청하면 서버에서 30초 동안 한 응답을 공유합니다. 화면의 조회 시각은 제공처 응답을 읽은 시간입니다.
- 지하철은 같은 역을 조회하는 노선 카드가 제공처 응답을 30초 동안 공유하고, 카드별로 해당 노선을 표시합니다.
- TMAP이 출발지와 도착지가 너무 가깝다고 반환하면 보행자 API에서 받은 시간과 거리로 도보 후보를 보여줍니다. 지도와 후보 목록은 같은 서버 인스턴스에서 도보 조회를 공유합니다. 예시 코스의 화성행궁 → 행궁동 카페거리가 이 경우에 해당합니다.
- 이름이 같은 정류소는 경로 제공처의 승차 좌표가 있고, 가장 가까운 동일 이름 정류소가 25m 이내이며 다음 후보보다 20m 이상 가까울 때 선택합니다. 그 외에는 정류소를 확인할 수 없다는 안내를 표시합니다.
- Vercel의 Content Security Policy는 스크립트와 지도 워커를 동일 출처로 제한하고 외부 프레임 삽입과 플러그인 실행을 차단합니다. 지도 출처는 앱이 직접 표시합니다. 교통 제공처 키는 서버 환경변수에 두세요. 서울 도착 정보의 공식 주소는 현재 HTTP이며 서버에서 제공처로 보내는 인증키가 암호화되지 않습니다. HTTPS로 응답하는 공식 엔드포인트가 확인되면 교체하고, 이미 노출된 키는 제공처에서 회전한 뒤 운영 변수를 갱신하세요.
- TMAP 무료 대중교통 한도는 한국 시간 기준 하루 10건으로 관리합니다. 운영에서는 무료 Upstash Redis에 `KV_REST_API_URL`, `KV_REST_API_TOKEN`을 연결하고 모든 함수 인스턴스가 한도를 공유합니다. Redis에 저장하는 값은 호출 횟수와 일시 중지 시각을 위한 만료 정보이며, 코스나 좌표를 저장하지 않습니다. 연결한 Redis가 응답하지 않으면 신규 TMAP 대중교통 호출을 멈춥니다. 연결하지 않은 개발 환경은 인스턴스별로 한도를 적용합니다. 제공처가 429를 응답하면 재시도 대기 시간을 반영합니다. 운영 연결 확인은 `/api/transport?action=status`의 `transitSharedBudget`을 참고하세요.
- 교통 API에는 출처 검사와 IP 기준 인스턴스별 호출 제한도 적용합니다. 신규 경로 요청이 제한돼도 이미 적용한 경로와 직접 입력한 이동 시간은 기존 일정에 남습니다.
